# Портативная версия для Mac (Apple Silicon): отчёт

30.09.2026, ветка `portable-mac`.

## Итог

Сборка `packaging/build.py --target mac-arm64` собрана и проверена на MacBook с Apple Silicon (macOS 26.3): чистая среда без uv, brew и кэшей, установщик одной командой, архив с карантином браузера через «Архиватор», двойной запуск. Все пробы прошли. Нажатие «Открыть всё равно» в Системных настройках проверено только имитацией (снятием карантина с одного «Запустить.command»): это настройка безопасности владельца машины, её не трогали.

| | |
|---|---|
| ZIP `dist/kadrovyi-agent-mac.zip` | 928 МБ (885 МиБ) |
| Папка `KadrovyAgent` | 1843 МиБ, 36 690 файлов |
| Минимальная macOS | 14 (Sonoma) |
| Сборка на маке | около 5 минут без загрузки весов |

## Что сделано

- `packaging/build.py` вместо `build_win.py`, цели `win64` и `mac-arm64`. Workflow `portable-win.yml` зовёт `python packaging/build.py --target win64`, Windows-ветка скрипта прежняя; сторож — `tests/test_packaging_mac.py::test_targets_keep_windows_and_add_mac`.
- Для Mac: python-build-standalone `cpython-3.12.*-aarch64-apple-darwin-install_only_stripped`; зависимости из `uv.lock` без dev с `--python-platform aarch64-apple-darwin` и `MACOSX_DEPLOYMENT_TARGET=14.0`. Без явной цели uv на новой macOS взял бы `orjson` под macOS 15, и на 14 агент бы не запустился.
- Скрипты `python/bin/*` ищут `python3.12` рядом с собой, а не по пути машины сборки, в том числе длинные заголовки через `/bin/sh`.
- Веса модели ложатся в `data/models` один раз (`flatten_cache`) и получают права 0644: с файла «только чтение» `xattr -dr` карантин не снимает, и после архива из Telegram вес модели оставался бы в карантине.
- Сборка падает, если в каком-нибудь файле остался путь домашней папки сборщика (`RECORD`, `.pth`, `.pyc`, `app.db`, конфиги) или в папке есть абсолютная ссылка. В итоговой сборке `grep -rl` по домашней папке пуст.
- ZIP пакуется `ditto -c -k --sequesterRsrc --keepParent`; скрипт распаковывает его `ditto -x -k` и проверяет, что `Запустить.command` и `python/bin/python3.12` исполняемые.
- «Запустить.command» переходит в свою папку, снимает с неё карантин, проверяет распаковку и macOS 14+, выставляет `TA_DATA_DIR`, `TA_MODELS_DIR`, `HF_HUB_OFFLINE=1`, `PYTHONUTF8=1` и запускает `python -m app.main`.
- `install-mac.sh` проверяет Apple Silicon, macOS 14+ и непустой `HOME`. Если на портах агента (8000–8010, или `TA_PORT` и десять следующих) `/health` отвечает с заголовком `X-Agent-Instance`, установщик просит закрыть окно агента и выходит: иначе старый сервер продолжал бы работать из перенесённой папки. Архив скачивается `curl` во временный файл и распаковывается в `~/KadrovyAgent.new`; место `~/KadrovyAgent` новая версия занимает только после успешной распаковки. Прежняя версия уходит в `~/KadrovyAgent.old-<дата-время>` и не удаляется, в конце печатается, где она. Временный архив и папку `trap` убирает при любом выходе. Потом установщик открывает папку в Finder, кладёт «Кадровый агент.command» на рабочий стол (macOS при этом может спросить про доступ Терминала к рабочему столу) и запускает агента. Адрес ZIP подставляется в строку `URL="__ПОДСТАВИТЬ__"` при выкладке.
- Признак экземпляра в `/health` считается от пути и inode папки данных и запоминается при старте: агент, чью папку перенесли в `.old`, не выдаёт себя за копию новой папки.
- Гонка в `app/embed.py`: на Mac torch считает на MPS, и два одновременных `model.encode` из разных потоков роняли процесс. Живая проба: 4 потока по 20 вызовов без замка — выход с кодом 139 (Segmentation fault), с замком — без ошибок. Теперь `encode` идёт по очереди под `threading.Lock`; сторож `tests/test_search.py::test_encode_runs_one_at_a_time`.
- Тексты клиенту: «Как запустить.txt» (`packaging/readme-client-mac.txt`) и сообщение для Telegram (`packaging/message-client-mac.txt`). Кнопки сверены со статьёй Apple https://support.apple.com/ru-ru/102445: «Системные настройки» → «Конфиденциальность и безопасность» → «Подтвердить вход», затем «Открыть».

## Пробы

Все пробы — с `TA_OPEN_BROWSER=0` на портах 8101–8105; свои процессы в конце остановлены.

1. **Чистая среда.** Архив распакован `ditto`, запуск через «Запустить.command» под `env -i HOME=/tmp/kadr-home PATH=/usr/bin:/bin:/usr/sbin:/sbin` (`packaging/smoke-mac.sh`). Первый запуск: `/health` через 28,3 с, пик памяти 1035 МиБ; повторный: 4,1 с и 691 МиБ. Все страницы ответили 200, плашка демо на месте, по вакансии демо найдено 40 кандидатов (первый поиск 0,6 с), своя вакансия даёт подсказку демо-режима без ошибки.
2. **Установщик целиком.** `python -m http.server` раздаёт `dist/`, `curl -fsSL http://127.0.0.1:8103/install-mac.sh | bash` с `HOME=/tmp/kadr-home2`. От старта команды до ответа `/health` — 70 с (скачивание 928 МБ с локального сервера, распаковка, первый запуск). Карантина нет ни на одном файле (`xattr -lr` — 0 совпадений), ярлык «Кадровый агент.command» на рабочем столе создан; запуск ярлыка при работающем агенте печатает «Агент уже запущен».
3. **Карантин.** На ZIP повешен атрибут как у Safari, архив открыт «Архиватором»: все 40 000 объектов внутри получили `com.apple.quarantine`, права на исполнение сохранились. Карантин снят только с «Запустить.command», запуск через `open` в новом окне Терминала: `/health` через 68 с (холодный старт после распаковки; на прошлой сборке 29 с), после запуска карантина нет ни на одном файле. `xattr -dr` по всей папке (43 417 объектов) — 2,7 с. На первой сборке этой пробы карантин оставался на весах модели (права 0444), это исправлено.
4. **Двойной запуск.** Второй «Запустить.command» на той же папке за 3,5 с печатает «Агент уже запущен: http://127.0.0.1:8102/» и выходит; второго сервера нет.
5. **Повторная установка (после ревью, сборка из HEAD).** Установка в чистый `HOME` через `curl | bash`: `/health` через 58 с, карантина нет, ярлык создан, `grep -r "plan-ai-recruiting"` по установленной папке пуст. Та же команда при работающем агенте печатает «Кадровый агент сейчас запущен…» и выходит с кодом 1, папки не тронуты. После остановки агента повторная установка: `/health` через 59 с, прежняя версия с базой лежит в `KadrovyAgent.old-<время>`, установщик называет её путь, временного архива не осталось.
6. **Размеры.** ZIP 928 МБ, папка 1843 МиБ.

## Минимальная версия macOS

python-build-standalone 3.12.14 (выпуск 20260929) собран под macOS 11. Самые требовательные колёса — `torch 2.14.0`, `numpy 2.5.3`, `scipy 1.18.1` с меткой `macosx_14_0_arm64`, поэтому итог — macOS 14. На macOS 13 «Запустить.command» и установщик говорят, что нужна macOS 14, и выходят. Mac на Intel не поддерживается: установщик об этом говорит.

## Почему архив 928 МБ

Сжатые размеры в ZIP: веса модели 456 МиБ (fp32 почти не сжимается), torch 120 МиБ, llvmlite и numba 42 МиБ (нужны только `ranx` для набора проверки `eval/`), onnxruntime 30 МиБ (`magika` из `markitdown`), scipy 19 МиБ, заголовки `torch/include` 10 МиБ. Безопасно ужать можно примерно на 50 МиБ: перенести `ranx` в dev-группу и убрать `torch/include`. Это правка зависимостей, в этот PR она не входит.

## Остаточные риски

- «Открыть всё равно» (в русской macOS — «Подтвердить вход») проверено только имитацией. Диалог Gatekeeper и Системные настройки не вызывались.
- Первый запуск после снятия карантина на машине клиента может занять больше минуты: macOS проверяет библиотеки при первой загрузке.
- Если Терминалу не разрешён доступ к рабочему столу, ярлыка не будет; клиент запускает «Запустить» из `~/KadrovyAgent`.
- Скачивание около 900 МБ; на медленном интернете установка займёт больше нескольких минут.
- Веса модели при этой сборке взяты из локального кэша Hugging Face: загрузка через прокси шла со скоростью 0,2 МБ/с. Скрипт сборки при этом отработал без изменений (`flatten_cache`, проверка без сети).
