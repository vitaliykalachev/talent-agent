# Отчёт по этапу 1 — каркас и импорт

Ветка `stage-1-skeleton`, последний рабочий коммит `2a096a2`. `make test` — 46 тестов зелёные, `make lint` чистый. `make demo` показывает на «Главной» 300 кандидатов, 15 объединённых дублей, 60 устаревших записей.

## Сделано

1. Каркас: `pyproject.toml` под `uv` (Python 3.12), `Makefile` (`run`, `test`, `lint`, `demo`), `Dockerfile`, `compose.yaml` с томом `./data:/srv/data`; запуск `uv run app`.
2. БД: все таблицы раздела 5 плана в `app/models.py`, SQLite в `data/app.db` (`TA_DATA_DIR`), миграция alembic `0001_initial` накатывается при старте.
3. Импорт (`app/importer/`): CSV (UTF-8/cp1251, `;`/`,`/таб, многострочные ячейки) и XLSX; маппинг колонок по названию и по содержимому (телефон, почта, ФИО, текст, даты — рождения или резюме по типичному году); папки и ZIP с PDF/DOCX/TXT через конвертеры markitdown, имена из Windows-ZIP (cp866) восстанавливаются; связка файла со строкой по ID в имени, по колонке имени файла или по ФИО (только при единственном совпадении). Экран «Загрузка базы» показывает догадку маппинга с примерами, пользователь правит и нажимает «Начать разбор».
4. Нормализация: телефоны `+7XXXXXXXXXX`, почта в нижний регистр, ФИО «Фамилия Имя Отчество» (по окончанию отчества, иначе natasha), город, год рождения, дата резюме из колонок или текста. Точные дубли по телефону или почте объединяются по всей базе: основной — более свежая запись, пустые поля дополняются, контакты складываются, старая получает `duplicate_of`, пара пишется в `duplicates` со статусом `merged`.
5. Фоновые задачи: таблица `jobs` (добавлено поле `total`), воркер на asyncio при старте; импорт пачками по 50 в одной транзакции, после перезапуска продолжается с первого необработанного; прогресс через HTMX-опрос раз в 2 секунды.
6. Экраны: «Главная» (счётчики, очередь внимания: устаревшие, нечитаемые файлы, дубли), «Загрузка базы», «Кандидаты» (поиск по имени, должности из текста и городу без учёта регистра, фильтры город и свежесть, страницы), «Кандидат» (контакты, исходник, связь с дублями); «Вакансии», «Утро», «Настройки» — заглушки. CSS в `app/static/app.css`, HTMX 2.0.4 локально; до 820 px таблицы становятся карточками.
7. Демо (`app/demo.py`, `make demo`): 300 человек по 60 на производство, финансы, продажи, ИТ, логистику; тексты четырёх видов; 60 устаревших (20 %), 15 дублей (5 %); CSV «как из CRM» плюс 134 резюме в DOCX (по ID) и TXT (по «Фамилия Имя»); идёт через обычный конвейер. Живёт в `data/demo/`, рабочую базу не трогает.
8. Тесты: маппинг, импорт всех форматов и связка файлов, нормализация, дубли (в том числе между загрузками; однофамильцы не склеиваются), продолжение прерванного импорта, все экраны 200, поиск и фильтры, фоновый импорт до `done`, демо-набор.

## Отклонения от плана

- Конвертеры markitdown вызываются напрямую по расширению: общий вход гоняет magika по 0,5 с на файл.
- Зависимость `setuptools<81` — без неё не грузится natasha (pymorphy2 и `pkg_resources`).
- DOCX для демо и тестов пишет свой минимальный генератор, без `python-docx`.
- Возможные дубли по rapidfuzz с подтверждением — по плану этап 4, не делались.
- Демо запускает импорт напрямую, минуя веб-форму, с догадкой маппинга без правок.

## Не успел

- `stale` считается только при импорте; записи, устаревшие позже, пометит ночной прогон этапа 4.
- 450 строк и файлов — 25–30 с (natasha и DOCX); база в 35 000 — порядка часа в фоне, замерить на реальной.
